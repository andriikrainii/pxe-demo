What that tells us

Five observations worth raising on Monday.

Concentration

Journey A is 7 of 15 — and all seven hit the same source

Every reporting workstream is BigQuery. The differences are rigour (Topline Pipeline self-QAs every figure; Monthly Report just renders) and orchestration (single vs multi-agent), not capability.

Seven near-duplicates is a consolidation question, not a feature list.

Demo choice

We're demoing the weakest of the seven

bigquery_monthly_report is single-agent, the only workstream flagged Needs review, and not published.

bigquery_insights_studio is multi-agent, Published, and does exactly what we demo — retrieve, report, present. Same tools, better standing.

Gap

Competitive Research Agent can't search the web

It's the only workstream in journey C without web_search_tool. Its description promises "comprehensive competitive research on any topic" — but it only has internal DB access.

Either a config miss or the description overstates it. Worth checking before anyone runs it.

Unused capacity

Six tools sit in the library, wired to nothing

api_connector_tool, social_post_tool, search_spec_tool, intake_tool, load_workstream_context_tool, analytics_chart_refine_tool.

api_connector_tool is the interesting one — it's the seam Amir's internal-tools theme plugs into, and it already exists.

Breadth

Only three journeys have a shared data source

A and B run on BigQuery. D runs on Upfluence + Mongo. C is web-only. E is document-only.

So "connects to your data" currently means BigQuery, one Sheets path, and one creator database — not a general integration story.

Shared output

Every journey can emit a report and a deck

research_report_tool and presentation_generator_tool are the only two tools enabled org-wide, and they appear on all 15.

That's the actual product claim: whatever the job, the output shape is consistent — which is what makes the locking story matter across journeys, not just reporting.
