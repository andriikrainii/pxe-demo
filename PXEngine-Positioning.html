Positioning

What PXEngine is, and the decisions that shape it

A companion to the feature inventory. The inventory records what the product does; this records why it is arranged that way, and what is still open.

The product in one sentence

A media team asks for a monthly client report in plain language. PXEngine queries the live warehouse, states what data it actually found, and shows the structure it intends to build before it builds it. The team edits that structure, approves it, and receives a branded report and deck in which every slide carries a type — so the same sentence produces the same shape next month, without anyone re-explaining it.

Who it is for

Read from the fifteen workstreams configured today, not from an intended market.

Recurring client reporting

Seven of the fifteen configured workstreams produce a monthly performance report from the warehouse. This is the load-bearing case: the same shape, every month, per client.

Diagnostics

Two workstreams look for what is wrong rather than what happened — anomaly detection, root cause, recommendations ranked by impact.

Competitive and market research

Four workstreams work from the web rather than internal data.

Sourcing and bid response

Two more: creator discovery against an external database, and RFQ response starting from an uploaded document.

The decisions that shape it

Seven choices that distinguish this from a tool that generates a document. Each one is implemented by features in the inventory, listed against it.

01
Nothing expensive runs before you approve the shape

A request produces a structure first — a numbered outline for a report, a typed row per slide for a deck — and generation waits. The outline is editable, rows can be excluded and reordered. One control governs both cost and quality, because a wrong structure is caught before the render rather than after it.

02
It states what data it does not have

The agent establishes the available range before answering. Asked for a month the warehouse does not hold, it reports the limit and produces the most recent complete month instead, in the thread, before any output exists.

F10F11F15
03
Structure is stored, not just content

Every slide carries a type — STATS, CHART, COMPARISON, STATEMENT, GRID, CTA and fourteen more. Because the shape is data rather than a rendering, it can be pinned, overridden per row, and reapplied on the next run.

F34F35F36F41
04
Corrections are retained

A format approved once becomes the standing default for subsequent presentations. The next run inherits it. No prompt is written and no model is trained; the correction is configuration.

F37F38
05
Presentation is separated from analysis

Branding is applied at render time from organisation settings. Switching theme re-skins output that already exists without re-querying the source or regenerating a sentence — which is what makes one system serve several clients.

F25F48F49F50F52
06
The platform tests itself, and escalates honestly

Each workstream drives its own workflow in a real browser, records the session, and reports what it finds. It applies the fixes it can and shows the actual edit it made. What it cannot fix is reported as an escalation with Retry, Flag and Skip rather than a green tick.

07
Spend and access are governed per workstream

The organisation approves which models may be used, and a request for an unapproved one is refused rather than substituted. Cost, latency and error rate are metered per workstream. A conversation is private to the people granted access.

Open questions

Three things the documentation surfaced that it cannot answer. These are product decisions.

Internal systems

api_connector_tool makes approved external HTTP calls and sits in the library configured on zero workstreams. The seam exists; the integration work does not. Until it is done, “connects to your data” means BigQuery, one Google Sheets path and one creator database.

Consolidation

The seven reporting workstreams all query BigQuery and differ in rigour and orchestration rather than capability. Whether that is a catalogue or a duplication problem is a product decision, not a documentation one.

Who the product is sold to

Everything above describes an agency running client reporting. Whether the same positioning holds for an in-house team is not something the current configuration can answer.
